Your dotfiles, applied#

Lepton is configured by a dotfiles repository, read at runtime from the files themselves rather than re-typed. The published ISO is built with Daniel Jaouen's dotfiles, as they are on GitHub (the build fetches them); build your own image with mix lepton.iso --dotfiles PATH.

The build installs the repository into /root following its own locations/ convention (*.symlink → ~/.name, *.directory.symlink → directories). Each program then reads its native file:

FileRead byWhat it gives you
~/.spacemacs, ~/.spacemacs.d/*.ellekey bindings, settings, theme (editor)
~/.tmux.conf (+ .tmux.linux.conf)tmuxprefix, key tables, options (tmux)
~/.zshrclshaliases, exports, options (shell)
~/.config/starship.tomllshthe prompt (shell)
~/.gitconfiggitidentity, aliases, settings (git)
~/.iex.exsiexyour IEx helpers (system)

keys (or keys editor|tmux|git|shell) prints exactly what was loaded. The key bindings page is generated from the same output.

Anything Lepton reads but can't apply is reported, never silently dropped: unsupported editor commands show as "not supported" in keys.
