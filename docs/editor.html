The editor: le#

le is a Spacemacs work-alike. It also answers to vi, vim, nvim, emacs, emacsclient, spacemacs and edit.

Read from your configuration#

le reads ~/.spacemacs and ~/.spacemacs.d/{editing,keybindings}.el with an Emacs Lisp reader, extracting define-key, global-set-key, evil-define-key, setq(-default), defalias and defun forms, including inside with-eval-after-load.

Spacemacs defaults#

  • the SPC leader with which-key popups: SPC f f/s files, SPC b b/d buffers, SPC w /,-,d,m windows, SPC g s git, SPC p f project files, SPC s s / SPC / search, SPC t n/r line numbers, SPC x a r align, SPC q q quit, SPC SPC M-x, SPC ? bindings;
  • helm-style candidate lists;
  • evil operators, motions and text objects with counts and ., visual modes, undo/redo, yank and paste, and splits;
  • keyboard macros: q and a register (a–z, 0–9) records what you type, q stops (the mode line shows [@q] meanwhile), @q plays it back, @@ plays the last one again, and a count repeats it (5@q). qQ (the capital) adds to macro q. Macros last until le quits;
  • ex commands: :w :q :wq :e :sp :vsp :s/// :sort :!cmd :r !cmd.

Org mode: folding#

In .org files, headings (* , ** , ...) fold as in Spacemacs:

KeysWhat they do
TAB on a headingcycle it: folded, then its child headings, then the whole subtree
S-TABcycle the buffer: top-level headings, then every heading, then everything
zm (zM)fold every heading: only the top-level ones show
zr (zR)reveal everything
za, zc, zotoggle, fold or open the heading the cursor is under

A folded heading ends in .... j and k step over folded text, and a search (/, n, N) that lands inside a fold opens it. Folds stay put as you edit above or below them; they last until the file is closed. o on a folded heading opens a line below its subtree; O opens one above, at the end of the entry before it, which stays folded. Lines you add while something is folded show until you fold again (zm, TAB).

Bindings that name commands le doesn't implement are listed as "not supported" by keys and SPC h d b, never silently dropped.

Git from the editor#

SPC g s opens a magit-style status buffer: stage with s, unstage with u, commit with c c, push with P p, pull with F p, and stash with Z. s and u take the file under the cursor, or on a section's heading (Unstaged changes, Untracked files, Staged changes) every file in it. As magit does, the status buffer first saves your modified buffers in the repository, so what you typed is what you stage.

To commit, press c c (or c a to amend the last commit): a buffer opens for the message, in insert state. Write it, then finish as in Spacemacs:

Keys
, c, , , or C-c C-c (also :wq, ZZ)commit
, k, , a or C-c C-kcancel

C-c C-c and C-c C-k work in insert state too. Either way you are back in the status buffer, with the commit ([main 1a2b3c4] Subject) in the echo area; then P p pushes. See git and GitHub.
