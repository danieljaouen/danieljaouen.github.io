ARM64 · Linux kernel · BEAM as PID 1

An operating system whose userland is written in Elixir.

Lepton boots on Apple Silicon virtual machines and runs everything you touch — init, the shell, a Spacemacs-style editor, a tmux-compatible multiplexer, git, a GitHub CLI and a package manager — as Erlang processes. It configures itself from your dotfiles.

Everything above the kernel is Elixir

        
Each program is a BEAM process with a Unix-style PID, connected by pipes that are Erlang I/O servers.


        

          

            
$_

            
lsh — the shell

            
Pipes, redirection, globbing, $(…), if/for/while, job control with C-z/fg, oh-my-zsh style emacs line editing, autosuggestions, syntax highlighting and a starship-compatible prompt.

          

          

            
λ

            
le — a Spacemacs-style editor

            
Evil operators, motions and text objects, the SPC leader with which-key, helm-style pickers, splits, ex commands, Monokai, relative line numbers and a magit-style git screen.

          

          

            
▤

            
tmux, in Elixir

            
Sessions that survive detach, splits, layouts, resize, zoom, vi copy mode and a themepack status line — all driven by your real ~/.tmux.conf, including if-shell.

          

          

            
⎇

            
git and GitHub

            
Format-compatible git (objects, packs, index v2) with clone, fetch, pull and push over smart HTTP. A gh CLI for repos, issues and PRs. Your gitconfig aliases just work.

          

          

            
⬢

            
lpm — packages from hex.pm

            
Resolves dependencies, verifies checksums and compiles Elixir and Erlang packages inside the OS. Packages can ship new shell commands.

          

          

            
⇩

            
An installer that writes disks

            
lepton-install writes a GPT, a FAT16 EFI partition and an ext2 data partition — all in Elixir — so your home directory persists across reboots.

          

          

            
⇄

            
Networking without C

            
Links, addresses and routes are configured over rtnetlink through :socket; a DHCP client runs at boot. ping, curl, ip and a text browser, www.

          

          

            
✓

            
Tested from the inside

            
lepton-test runs the same ExUnit suite inside the booted OS that runs on a laptop — mounts, drivers, DHCP, even cloning a repo from GitHub.

          

          

            
⏻

            
Behaves like a real machine

            
PID 1 mounts filesystems, loads kernel modules from modules.dep, logs in every console, and shuts down cleanly when the virtual power button is pressed.

          

        

      

    


    
    

      

        
Configured by your dotfiles — not a copy of them

        
The build installs a dotfiles repo into /root. Each program then reads its native config file at boot. keys shows exactly what was loaded.

How it fits together

        
Lepton is honest about its foundations: a stock Linux kernel and the Erlang runtime sit below; everything that defines behaviour is Elixir.


        

          

            

              Elixir userland
              lsh · coreutils · le · tmux · git · gh · lpm · www · installer
              TTYs & line discipline · VT emulator · netlink + DHCP · init
            

            
Erlang/OTP 29ERTS, kernel, stdlib, ssl, crypto, inets

            
Linux 6.18Alpine virt kernel · glibc · GRUB (UEFI)

            
ARM64 VMUTM · QEMU · Apple Silicon

          


          
    
            
  1. UEFI finds the El Torito image on the CD — or the GPT partition on the hybrid ISO when attached as a disk.
    2. 
            
  2. GRUB loads the kernel and initramfs; both were packaged by Lepton's own Elixir cpio, FAT and ISO 9660 writers.
    3. 
            
  3. Linux executes ERTS directly as /init; the kernel command line carries the runtime's flags.
    4. 
            
  4. Lepton.Init (PID 1) mounts /proc, /sys, /dev, loads drivers and mounts the persistent disk.
    5. 
            
  5. Sessions open on the display and serial consoles, each a TTY process running lsh, configured from your dotfiles.
    6. 
          

        


        

          What isn't Elixir, and why
          

            
LayerSourceWhy

            
              
Linux kernel + modulesAlpine linux-virtThe BEAM needs a kernel.

Get started

        

          

            
1 Get the ISO

            
Download it, or build your own (with your dotfiles) on Elixir/OTP 29:

            
git clone --recursive https://github.com/danieljaouen/lepton
cd lepton
mix lepton.iso          # -> out/lepton.iso

          

          

            
2 Boot it

            
In UTM: Virtualize → Linux → choose lepton.iso. Add a serial device to get a second console. Or use QEMU:

            
mix lepton.qemu         # window, like UTM
mix lepton.qemu --test  # headless: boot and run the self-tests

          

          

            
3 Install and explore

            
Add a VirtIO drive, then inside Lepton:

            
lepton-install          # GPT + EFI + ext2, all in Elixir
lepton-tutorial         # a 10-lesson tour
lpm install jason       # packages from hex.pm
keys                    # bindings loaded from your dotfiles

          

        

      

    


    
    

      

        
Roadmap

        

          
Done
A complete CLI system
Shell, editor, multiplexer, git & GitHub, packages, installer, networking, graceful shutdown.

          
Next
Graphics
Pixels to the framebuffer from Elixir, input from evdev, then a compositor where windows are processes.

          
Later
A real browser
www already fetches and lays out HTML as text. CSS, box layout and rendering to the compositor come next.

          
Later
Wi-Fi
Credentials are saved today; joining networks needs a kernel with an 802.11 stack and a WPA client.
